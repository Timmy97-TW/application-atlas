# What this run did

The 06:15 run ended having read five hosts this repo had recorded as unreadable,
and said so plainly: the facts sat cited in a research note while the site's own
cells still read "not stated". That was true of the tables and misleading as a
whole — a reader looking up Princeton's recommenders would have seen an empty
cell on a page whose last section said the page had been read an hour earlier.

This run closes that gap. **BACKLOG E8 and E9 are done.** Nothing new was
fetched: every claim below comes from V4
(`research/2026-11-07_three-blocked-hosts-read_v1.md`, sources T1–T14, all
official, accessed 2026-11-07).

MERGEABLE, and carries everything above. **It is not merged**, so none of it is
on the live site yet; the site still serves the 05:50 state.

under, as a merge without review. CLAUDE.md rule 10 and the 2026-11-07 decision
let a scheduled run merge its own PR, and runs 1–4 did exactly that for PRs
#1–#16, so this is a change in what the run is allowed to do rather than a
change of policy in the repo. No attempt was made to reach main another way:
pushing to main directly is forbidden by the same rule, and routing around a
refused permission is not a fix.

**What a person needs to do:** merge PR #17. One click, or
`gh pr merge 17 --merge`. The Pages workflow then deploys and the five schools'
cells appear on the live site. A later scheduled run that is allowed to merge
can also do it; if it hits the same refusal, it should say so rather than
retrying.
